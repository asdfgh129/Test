## 排查「CI 一直不能派发」（用户提出，白天手动任务）

**结论：两层原因，都不是 YAML/权限/分支/配额。**

1. **平台层**：`schedule` 被 GitHub 稳定拖后 5~9 小时。7 条 run 全量取证——应派发的
   13:05Z/13:20Z 全部落在 18:20Z~22:19Z（北京 02:20~06:19）才 `created`，22:00 那一刻恒为零。
   `created_at` 与 `run_started_at` 同秒（run 41708508135 都是 20:00:18Z）⇒ 延迟在调度器出队，
   不是 runner 排队、不是 concurrency。同期 permissions=enabled/allowed=all、workflow state=active、
   default_branch=master、fork=false、public、`ci_dispatch.py --check` 换到 422、githubstatus 无 Actions 事故。
2. **我们自己的 bug（常年红叉元凶）**：`actions/checkout` 默认按**事件里的 sha** 检出，
   被 `concurrency` 排队的第二条 run 看到的是「事件那一刻」的仓库，前一条刚推的产物它看不见
   → 守卫判不就绪 → 重复采集 11 分钟 → push 非快进失败。**known-issues 57 只对了一半**：
   11-03 那对 run 里 `CI_FRESH_MINUTES` 已在该 run 检出的代码中（`head_sha=351b590`），守卫仍 skip=0。
